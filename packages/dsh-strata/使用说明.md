# 记忆地层 · 使用说明

打开 **设置 → 记忆地层**。

1. 在“范围与授权”选择 **同工作区的其他会话**，保持“检索历史会话片段”开启。A1 会按相关性引用 A2–A5 的历史。
2. 要查 B，勾选 B。可以指定一次召回、本会话或长期；关闭“启用已勾选的跨工作区读取”可以暂停所有外区读取，保留选择。
3. 全局偏好使用“读取全局记忆”独立开关。要新增全局记忆，先开启“允许保存全局记忆”，再把默认保存范围改为全局。
4. 在“上下文力度”选择轻量／均衡／深入。预设只改数量和预算，不会勾选新的工作区。“注入写入提示”控制注入块里那段“什么时候值得记”的规则：默认“克制”（多数轮次什么都不用记），选“积极”更容易攒下内容也更容易攒噪声，选“关”则只注入资料。**记忆库为空时这段规则照样会注入**——否则模型不知道这里可以记东西，会一直不写。
5. 在“召回预览”输入查询，必要时限定来源 B，查看完整注入文本。预览不会消耗一次性授权。

手工保存和预览需要工作区。页面默认跟随实际会话；如果没有当前会话，先选择工作区。保存本会话记忆还需要绑定会话 ID。页面中的手工选择不会改变自动召回使用的真实会话身份。

让模型续接工作时可以说：

> 搜索当前工作区其他会话中关于部署方案的记录，带上来源，再继续实现。

勾选 B 后可以说：

> 查 B 工作区之前对这个接口的决定，结合当前项目继续处理。

长期记忆可通过“记忆管理”保存，或说：

> 把这个决定记到当前工作区：依赖统一使用 pnpm 安装。

取消勾选阻止后续读取，已经注入的内容仍在原会话历史里。历史片段是引用，可能包含过时结论；当前用户要求优先。

**一个话题做完就交接，然后新开会话** —— 这是整套插件里最省钱的一步：贵会话里 71.5% 的发送 token 是继承来的历史，重开能砍掉这一大半。交接由模型调 `memory_handoff` 完成，你也可以直接说：

> 这个话题做完了，用 memory_handoff 存一条交接，然后我们新开一个会话。

它把你的结论／决定／待办，加上最近几条原文，压成一条**工作区**记忆；中间那部分只留一条“用 `memory_recall` 取回”的指路条。**默认是纯本地压缩，不花模型钱**；只有你明确要一份“真的写出来的摘要”时才会花一次模型调用，而且压完不比原文短就不落地（花了钱也会把 token 数报出来，并记进 `~/.dsh/strata/events.log` 的 `kind:"handoff"`）。

新开会话后，**即使你的第一句话跟上次话题毫不相干**（比如“继续昨天的活”），注入块里也会出现一行 `- [交接·今天] 上次交接：memory_recall("…") 取回结论与待办。`，模型据此就能把交接拉回来。这条索引行只有一行，14 天后不再主动提；被“遗忘”的交接也不会再提。

**想看这个插件到底往上下文里塞了多少**：设置页最下面的「存储与运行信息」里有「常驻注入块 X 字符 / Y token · 近 24 小时注入 N 次 · 付费模型调用 M 次」；也可以直接问模型「跑一下 memory_stats」，它会报同一份账本并说明每一项的含义。两个数别搞混：**常驻块**是接下来每一轮都要重付的那一份；**累计**会把同一个块每替换一次就再记一遍，不能当账单读。宿主没有金额服务，所以 token 是插件自己按内容算的估算，不是账单；付费档只要试过（哪怕白花的、失败的）都会计入调用数。

## 悬浮窗（不用离开对话就能看状态）

插件会在窗口右下角放一个**可拖拽的小面板**，标题「记忆地层」。它每 2 秒自动刷新，显示当前会话的实时状态：

**先看最上面那格：这个数字属于哪个会话。** 面板顶部用一行**会话身份块**回答「我现在看的是谁的数据」：

- 会话号（太长会截断成 `abc…xyz`）—— 后面跟一个小徽章，标出当前口径：
  - **自动** —— 你没手动选过，面板自动跟到**最近活跃的那个会话**（不再把全库混在一起算）。
  - **已选** —— 你从下拉框里手动选的会话（事件流里有它）。
  - **新会话** —— 你手动选的会话还没产生任何事件（刚建的空会话）。
  - **按工作区** —— 按工作区聚合。
  - **合计** —— 你显式选了「全部会话（合并）」。
  - **空** —— 事件流里一条记录都没有。
- 副标题给出这个会话最后活跃时所在的工作区（**只显示目录名最后一段**，不暴露完整路径）。

下面还有一个**下拉切换器**：默认「最近活跃（自动）」，展开可列出事件流里出现过的所有会话（带各自的事件数和所属工作区），最后一项是「全部会话（合并）」。**手动选过一次就会记住**（存在浏览器本地），刷新/重开都还停在你的选择上；想回到自动，选回第一项即可。

再往下是各项指标：

- **常驻注入块** —— 此刻每一轮都要重付的那一份有多大（字 / token 估算）。
- **本会话注入 / 首次注入** —— 这个会话一共注入过几次、第一次是什么时候，也就是「插件从哪一刻开始干活」。
- **压缩** —— `开始压缩`（第一次交接的时刻）、`压缩次数`、`压缩效率`（body ÷ material 的百分比，下面有进度条）、`素材 → 存下`。**注意这里只统计 `memory_handoff` 的真压缩**，注入块的 version-replace 不算压缩（它只保证体积不随轮数增长，本身不省东西），旁边单独一行标出。
- **省下（估算）** —— 相对「不装插件」的字符 / token 估算，以及累计付费调用次数。**金额恒为 `–`**：宿主没有计价服务，插件**绝不编一个金额出来**。
- **时间线** —— 最近若干条事件（注入 / 交接 / 召回 / 写入 / 付费），一眼看清「在什么地方开始压缩的」。

> **为什么是「自动落到最近活跃会话」而不是全库合计**：DSH 桌面版的页面走 `dsh-app://` 自定义协议，URL 里**拿不到当前会话号**，插件无法确知你在哪个会话。早先的做法是退化成「全库混算」，但那样面板上的数字根本不是这个会话的，反而误导。现在的做法是默认跟到**事件流里最后活跃的那个会话**，并在顶部**明确写出来**是哪个会话、什么工作区、什么口径 —— 你要看别的会话，用下拉框切换即可。

面板右上角：「–」折叠成一条标题栏，「×」隐藏；隐藏后在右下角留一个小的「记忆地层」把手，点一下回来。位置会被记住，下次打开还在原地。

> **口径提醒**：token 和「省下」都是**估算**，不是账单。想验证插件是否真省了，请用 `docs/` 里的对照报告和上面的三个口径，不要拿悬浮窗的数字当发票。

日志丢失时插件无法恢复原始历史。已明确保存的长期记忆独立保存在 `.dsh/strata/memories.jsonl`。如果有会话备份，可以在配置的 `extraSessionRoots` 中指定备份会话根目录。

保存失败会在页面顶部显示原因，原输入保留。刷新连接后可重试；不要把未确认保存的开关状态当成已经生效。

模型不能使用 `memory_scope action=grant` 自行开放 B；必须由你在设置里勾选。授权允许读取，不允许模型修改 B 的长期记忆。
