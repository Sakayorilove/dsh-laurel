# Product context

This is an independent browser appearance plugin for DeepSeek Harness 0.2.0-rc.2, named dsh-claude-parchment. The user wants the warm yellow parchment character of Claude's 2025 interface in both light and dark modes, while leaving every other installed plugin untouched.

The plugin adds a settings section and one opt-in appearance layer. It follows the host's existing light/dark/system preference and content font-size preference. It defaults off, stores only its own enabled preference locally, and never touches anything outside its own layer. Appearance controls do not write other plugins' preferences or profiles, change model configuration or access conversation data. A manual update explicitly requested through its form delegates installation changes to the official Harness installer.

The preview uses illustrative Chinese conversations and emulates public host services. It is a design and browser integration fixture, not a replacement application or a real chat session. The distributable contains a browser ModuleLoader client entry and an empty Host companion, with no runtime npm dependencies. Installation in the user's running application has not been performed.

The pinned aesthetic is warm paper, terracotta accents, serif reading text and welcome title, sans interface labels, restrained borders and warm charcoal in dark mode. No logo substitution or proprietary font assets are required.

Version 1.1.0 extends the theme to the conversation layout: a centered 720px default transcript sharing its width axis with the composer, serif answer prose with deliberate paragraph/heading rhythm, and quieter user message rectangles. Host font-size preferences and manually dragged conversation widths remain authoritative. Collapsed reasoning, tools, actions and code retain their own roles. Disabling the appearance layer retracts the conversation styling together with the palette.

Version 1.2.0 adds the compiled loaded version beside the heading, an independently queried installed version, a local version check, and an inline manual update form. A verified installation still requires a full restart; only the running client version proves activation. The plugin is distributed as local versioned tgz files, with no public release source. Manual updating calls the official remote listBundles/inspect/installBundle API and preserves host supply-chain policies; it never authorizes build scripts or edits package-manager policy. The theme remains usable when the remote installer is unavailable. Mock-host tests cover update and failure paths; actual Desktop updating has not been performed by this work.

Version 1.3.0 is an additive appearance-system extension authorized by the user: preserve Claude Parchment and offer Robinhood · Lime, Binance · Gold and Bitget · Cyan as three minimal trading-terminal alternatives, each with a light and dark partner. The new variants use system sans-serif reading text, quiet surfaces, a single action accent and small focus/hover light effects. Names describe the requested references; this is an independent interpretation, not an official theme or a reproduction of proprietary assets. No logos, images, font assets or runtime dependencies are added.

Four native radio rows choose the theme independently from the Enable selected theme switch. Enabled selections apply immediately; selections made while off are saved for the next enable. The same plugin-owned local preference stores enabled and theme. Older enabled-only preferences retain their enabled state and select parchment; unknown theme values also fall back to parchment. All variants continue to follow General appearance and the host's content-size and conversation-width preferences. The settings surface is available through Laurel control center or the standalone theme section.

The 1.3.0 implementation was checked with 20 passing tests and 12 browser-fixture theme/mode/viewport combinations, with evidence under `<HOME-USER>/projects/parchment-trading-20261015-evidence`. These are mock-host browser checks, not acceptance in the user's real Electron session. The historical installation statements above describe their original work; current installation and running activation must be verified separately from source/package version.

Version 1.3.1 extends the user-authorized terminal appearance system with distinct geometry and structural depth: Robinhood uses square corners, Binance small corners, and Bitget softer corners with an asymmetric user/steering bubble. Terminal user bubbles and the sidebar gain restrained shadows with light/dark-specific ink. Composer, primary actions, navigation, code blocks and this plugin's settings controls follow their selected geometry. Parchment's palette, radii and shadows remain unchanged; no new preferences, assets or runtime dependencies are introduced.

Sidebar depth is painted on the host's clipping column itself, with the nested sidebar root shadow cleared. Existing overflow, sizing, resize handles and collapse geometry stay authoritative. Only the desktop column receives the local stacking adjustment; mobile keeps its existing fixed positioning and stacking rules. Twelve mock-host combinations, including mobile sidebar expanded/collapsed fixtures, passed under `<HOME-USER>/projects/parchment-shapes-20261015-evidence`. This documents browser-fixture evidence rather than real Electron acceptance.
