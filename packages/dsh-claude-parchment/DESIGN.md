# Design System: Claude Parchment

## Overview

**Creative North Star: "Warm Paper for Work"**

Quiet, warm paper supports reading and operating. Cream parchment in light mode becomes warm charcoal in dark mode; terracotta marks action while serif reading text gives the transcript a bookish cadence.

This is an appearance extension: the host retains the sidebar, transcript, composer, control hierarchy and behavior. The same visual roles apply in both modes. Theme overrides act only while enabled; the plugin-owned settings section remains usable in every state.

Version 1.3.0 adds three user-requested alternatives alongside this incumbent paper world: Robinhood · Lime, Binance · Gold and Bitget · Cyan. Their shared character is a quiet trading terminal: neutral surfaces, sans reading, one decisive accent and light limited to meaningful interaction. The parchment world and its tokens remain intact. These are independent interpretations of public product style, not official palettes or copied interfaces.

Version 1.3.1 makes each terminal silhouette distinct: square Robinhood, compact Binance and softer Bitget with an asymmetric bubble corner. User bubbles and sidebar edges gain structural shadows, while the parchment geometry and depth stay intact. These are additions to the selected terminal world, with no new interaction model or preference.

**Key Characteristics:**

- Yellow cream and warm charcoal, paired by semantic role.
- Serif reading and welcome; sans controls; monospace code.
- Restrained strokes, gentle corners and a flat composer.
- One opt-in appearance layer; existing functional plugins remain authoritative.
- Three optional terminal variants share the same host hierarchy and paired light/dark roles.
- Terminal-specific geometry and restrained bubble/sidebar depth make each selected variant recognizable.

## Colors

The frontmatter records the published light/dark palette pairs. Names mirror the source roles; host semantic aliases reuse these values rather than introducing extra palettes. Existing unprefixed `light-*` / `dark-*` tokens are parchment. New `robinhood-*`, `binance-*` and `bitget-*` pairs are expanded directly from the exported `themes` object, including shared terminal roles; that source remains authoritative.

### Primary

Terracotta and its hover partner identify primary actions and focus. Brown links remain distinct from action fills. The on-accent pair supplies legible button text.

**The Single Accent Rule.** Terracotta identifies parchment primary actions, brand and business markers, caret and focus. Terminal variants use their selected lime, gold or cyan accent in the same roles. Status and syntax colors retain their existing meanings.

The Robinhood variant pairs a near-black olive cast with bright lime in dark mode and a readable deeper green in light mode. Binance pairs graphite with gold, using a deeper gold-brown light accent. Bitget pairs cool black with ice cyan and a deeper teal light accent. The light partners prioritize readable accent text and action fills; they need not match dark accent brightness. These descriptive names identify this implementation's choices, not measured brand standards.

### Neutral

Paper canvas, darker sidebar paper, clean surfaces and raised paper create quiet layers. User bubbles, hover and selected paper separate conversation and navigation states. Reading, secondary and muted ink establish hierarchy; quiet and strong borders mark structure and fields.

Selection, code and tooltip pairs serve their named surfaces. Success, warning and error pairs are semantic feedback; constant, string, keyword and function colors are syntax roles, not additional brand accents.

Terminal variants use cool neutral ink and subdued surfaces with small hue shifts around the chosen accent. The shared terminal base supplies status and syntax roles while each variant overrides canvas, sidebar, interaction fills, accent and selected supporting surfaces. Decorative theme previews show canvas, surface, accent and text in that order.

## Typography

Serif stacks fall back across Latin and Chinese system fonts; no font asset is bundled. Sans controls inherit the host's size. Code retains a system monospace stack.

Welcome uses the display role; the same brand stack and weight style host title text without imposing a title size. Assistant prose uses locally overridden host Markdown font roles, because the renderer's explicit font shorthand overrides inherited flow-seat fonts. Heading ratios are 1.5 / 1.25 / 1.125 / 1 times the user's body size, at weight 600; paragraph spacing is 1em. Dark prose slightly increases leading to 1.85. Composer copy uses the control family with its own line height. Compact reasoning, buttons, code banners and tool controls retain sans or monospace roles.

The terminal variants bind both reading and welcome/title roles to the existing UI sans stack. Their title weight is 600 with tighter tracking (-0.025em), while reading leading is 1.75 in both modes. The existing welcome sizes, paragraph and heading rhythm, control roles and code stack remain shared. No new font is installed or fetched.

**The Font Division Rule.** Use serif for parchment assistant prose and welcome; use sans for terminal reading, welcome and all controls; use monospace for code. Preserve the host's content font-size preference.

## Layout

The host owns composition, sidebar behavior, scrolling, composer placement and controls. Version 1.1.0 sets the public conversation width axis on `[data-conversation-content]`: a centered 720px default, constrained by available host column width minus 64px. An explicit `--dsh-chat-user-width` still controls user-dragged sizing. The composer uses the same axis plus 32px, preserving host alignment and width handles.

User bubbles cap at 88% of the transcript (94% below 600px), use the selected theme's bubble geometry (parchment remains 12px) and 12px × 16px insets. Conversation turns have 28px separation (24px below 600px), while operational rows retain the host's compact spacing. Tables stay within the reading column and scroll locally; they no longer break into the surrounding page gutters. The active-conversation preview contains two turns and no empty-state welcome banner, with host-shaped user stacks and Markdown font shorthands.

Only the plugin settings section owns an inset and a maximum width (760px); its toggle row uses the row inset and gap tokens. At the compact threshold (600px), the welcome switches to display-compact, composer text uses composer-compact, and settings uses settings-compact-inset. This threshold does not promise a particular host sidebar or modal behavior.

The four-theme chooser is a vertical native-radio fieldset, not a card grid. Each row has a minimum height (72px), horizontal/vertical padding (4px / 10px), a radio, a two-line name/detail block and four decorative color bars. Its flex layout keeps the text shrinkable and the controls/swatches stable. The existing settings maximum width and compact inset apply to every selected theme.

Terminal sidebar shadows belong to the clipping column wrapper so they can reach the conversation without changing its existing hidden overflow. The nested sidebar root clears its own shadow to avoid doubling. The desktop wrapper uses a local stacking level (1) from 601px; mobile fixed positioning and stacking remain host-owned. Widths, resize handles and collapse geometry remain unchanged.

## Elevation & Depth

Tonal layering is primary. Parchment host shadow aliases receive small ambient lifts: low (`0 2px 6px rgb(40 28 15 / 5%)`) and raised (`0 6px 18px rgb(40 28 15 / 9%)`). Menus disable backdrop filtering. The composer has no resting shadow.

**The Paper Depth Rule.** Use tonal separation and restrained strokes. The parchment composer is flat at rest and gains a one-pixel focus stroke without a blurred glow.

Parchment adds no motion duration or easing. Terminal variants use low (`0 3px 10px rgb(0 0 0 / 10%)`) and raised (`0 8px 24px rgb(0 0 0 / 16%)`) host shadows. Their local glow mixes the active accent at 16% with transparency. Composer focus adds a one-pixel accent stroke and a small lower glow (`0 4px 18px`); enabled primary-button hover uses a small glow (`0 3px 12px`). Border/background/shadow state transitions use 160ms ease-out. With reduced motion requested, transitions are removed from the composer, chat flows and buttons.

**The Interaction Light Rule.** Terminal glow marks composer focus and enabled primary-action hover. Keep large canvas and idle surfaces quiet; do not add ambient decorative illumination.

Version 1.3.1 adds terminal user/steering bubble shadows: Robinhood uses `0 2px 7px`, Binance `0 3px 10px`, and Bitget `0 5px 16px`, each with light ink (`rgb(12 22 29 / 12%)`) or dark ink (`rgb(0 0 0 / 32%)`). Terminal sidebar depth is shared: light (`5px 0 18px rgb(12 22 29 / 13%)`) and dark (`6px 0 20px rgb(0 0 0 / 34%)`). These are structural shadows at rest, distinct from the small colored interaction glows; parchment receives neither addition.

## Shapes

The composer uses the panel radius and a strong border (1px). Panel, medium and small radius aliases style whichever host components consume them; they do not define every host control's silhouette. Conflict help uses its local radius; palette swatches are circular with a strong border (1px).

Terminal geometry is theme-specific from 1.3.1; the rounded frontmatter tokens are normative. Robinhood uses square panels, controls, navigation, bubbles and sidebar edges. Binance uses small panel/control/bubble corners (4px), slightly tighter navigation (3px), and right sidebar corners (4px). Bitget uses soft panels and right sidebar corners (12px), smaller controls (6px), medium navigation (8px), and a user bubble with a tighter bottom-right corner (12px 12px 3px 12px, clockwise from top-left). Sidebar left corners stay square in every terminal variant.

Panel geometry feeds the composer and large host radius aliases. Control geometry feeds small/medium host radius aliases, primary actions, code block/banner corners and this plugin's settings buttons/path inputs; the terminal rules only apply while the selected appearance layer is active. The native radio/checkbox affordances keep their browser shape. Theme chooser rows use horizontal rules without a surrounding card. Their adjoining color bars round only the outside corners (4px) and remain decorative. Parchment retains its original panel, message and control values.

## Components

- **Primary actions:** accent fill and on-accent text; enabled hover uses accent-hover. Host geometry and disabled behavior remain authoritative.
- **Composer:** clean surface, strong border and no resting shadow. Focus within changes the border to accent and adds an accent stroke (1px). Placeholder uses muted ink; caret uses accent.
- **Navigation:** sidebar paper with selected and hover fills. The existing rows and mobile behavior remain host-owned.
- **Reading and code:** assistant prose is serif with deliberate heading and paragraph rhythm; code is monospace on code paper, with sans banners and semantic syntax colors. Links have an underline offset (0.2em). User messages have a restrained paper rectangle; answers read directly on the canvas.
- **Keyboard focus:** existing host outlines are tinted accent and offset (3px); the theme does not prescribe outline width or style.
- **Settings:** a native checkbox exposed as a switch, readable status and storage errors, conflict help when paused, and decorative palette swatches. These use host semantic aliases even when the appearance layer is inactive.
- **Version and update controls (1.2.0):** a quiet version beside the title, two aligned loaded/installed rows with tabular numerals, explicit mismatch/restart feedback, and Check version / Manual update controls. Manual update expands a labeled full-width path field and an installation action within the section. Disabled/loading/error states remain readable whether the theme is on or off. All colors use existing host semantic aliases; no extra modal, icon or palette is introduced. Desktop and mobile settings and update-form states were checked together.
- **Theme chooser (1.3.0):** four native radio rows with a fieldset legend, accessible theme names, descriptive text and aria-hidden color bars. The selected name and radio use the host accent; hover uses the host hover fill; keyboard focus has an accent outline (2px) with offset (3px). Enabled switching replaces the single appearance layer immediately. Choosing while off only records the selection. The enable switch and existing local error feedback remain separate from selection.
- **Terminal interaction variants (1.3.0):** the selected navigation row gains an inset accent marker (2px); composer focus and primary-action hover use the Interaction Light Rule. The editable area's terminal focus outline is suppressed because its surrounding composer card supplies the visible focus indicator. Terminal answer prose uses sans. Host interaction, dimensions and mobile navigation behavior remain authoritative.
- **Terminal geometry and depth (1.3.1):** use the selected variant's panel/control/navigation/bubble/right-sidebar tokens consistently. User and steering bubbles receive their variant shadow; the sidebar wrapper owns its single shared mode-specific shadow. Code containers and the theme's settings action/path controls use the control radius. The host continues to own element dimensions, clipping, resize and mobile collapse behavior.

The sidecar renders a tight set of standalone specimens: parchment/terminal action buttons, three terminal sidebar/bubble/composer studies, native theme chooser, enable control and update path field. The terminal studies show the implemented radii and depth; their composition and dimensions remain illustrative. Settings specimens use host aliases; their fallback colors only support standalone rendering. Derived tonal ramps are panel aids, not additional shipped tokens.

## Do's and Don'ts

### Do:

- **Do** keep the same controls and hierarchy across light and dark modes.
- **Do** apply the paired semantic tokens from src/palette.mjs.
- **Do** preserve the host's scroll logic, chosen content size, user-dragged width and other plugins' functional enhancements.
- **Do** keep original parchment available when adding terminal choices; choose the whole semantic pair rather than mixing theme accents and surfaces.
- **Do** limit terminal light effects to focus and enabled-action hover, and honor reduced motion.
- **Do** apply each terminal's geometry as a set, paint sidebar depth once on its wrapper, and preserve host clipping and mobile stacking.

### Don't:

- **Don't** add illustration, brand logos, proprietary fonts or background glow; parchment keeps its original no-glow treatment.
- **Don't** style host surfaces while the theme is disabled or paused.
- **Don't** promote preview column widths, modal geometry or button dimensions into host guarantees.
