# 内耗护栏 · 设计说明

给要改这个插件的人看。重点不是「代码长什么样」，而是**每条决定背后的那个坑**。

---

## 0. 一句话架构

```
lib/core/     配置（三档预设）、文本与哈希、数据层（锁/台账/计数器）、持久化
lib/host/     guard.js（执行前）· after.js（执行后）· inject.js（上下文）
              tools.js（模型侧 6 个工具）· http.js（设置页的数据面）
lib/index.js  入口：把上面三组挂起来，管总开关的热生效
lib/client/   设置页（构建产物是 lib/client.js，不要直接改产物）
```

三条钩子链是**独立挂载、独立卸载、独立吞异常**的。`installGuard` 挂失败不会影响 `installAfter` —— 这是刻意的：任何一条链出问题，其余功能照常，插件也不会把宿主带塌。

## 1. 宿主契约（从 `app.asar` 实读核对，不是猜的）

这一节是**最重要的一节**。下面每一条都踩过或差点踩过。

### `tools/pre-execute` —— waterfall

```
(exec, next) => decision
```

- **不拥有这个决策时必须 `return next()`。** 忘了就等于把这次工具调用「否决」掉 —— 模型侧只表现为「工具坏了」，报错在宿主深处。
- 要拦：`{ kind: 'deny', reason }`。**不是 `reject`**。
- 要问用户：`{ kind: 'ask', reason, displayReason: { zh, en } }`。
- 兜底值：`{ kind: 'allow' }`。还有一个 `{ kind: 'final-result' }`。
- `exec` 上可用：`name` / `arguments` / `agent` / `signal` / `callId` / `parent`。
- ⚠ `exec.arguments` 有两种形态：**已解析的对象**，或 **JSON 字符串**。两种都要认，写回时保持原形态（`readArgs` / `writeArgs` 就是为这个存在的）。

### `tools/post-execute` —— waterfall

```
(exec, result, next) => decision
```

- `{ kind: 'accept', content?, additionalContexts? }` 保持成功
- `{ kind: 'block', feedback, additionalContexts? }` 变成 isError
- **`additionalContexts` 是消息数组**，会被宿主挂到结果上、进入下一批上下文。这就是官方 `dsh-repeat-tool-reminder` 投递提醒的同一条通道。
- 下游可能是 `accept` 也可能是 `block`，**两种都要把提醒带上**，所以是 `{ ...downstream, additionalContexts: [...notices, ...existing] }`。

### `agent/pre-step` —— waterfall

```
(payload, next) => decision
```

- `payload` = `{ agent, messages, turn, signal }`
- 必须先 `await next()` 拿到最终批次，再在它之上改。
- **只在 `decision.kind === 'enter'` 上动手。**
- **改写必须 spread**：`{ ...decision, messages }` —— 否则 `startsRequestSeries` 之类的字段会丢。

### `llm/stream` —— waterfall，**不是广播**

⚠ 这一条最贵。回调必须把 `next()` 的返回值交还回去，否则整条链被「否决」，`llm.stream()` 变成 `undefined`，宿主 agent-loop 里 `for await (const chunk of undefined)` 直接抛：

```
Cannot read properties of undefined (reading 'Symbol(Symbol.asyncIterator)')
```

表现为「本轮运行失败」，整轮对话打不出来。所以 `rememberUsage` 最后一定是 `return next()`。

### 系统提示词

`ctx.systemPrompt.section({ name, order, text })` 是官方点名的做法（原文：*Add prompt text with `ctx.systemPrompt.section()`*），而且**明确禁止**用 `system-prompt/assemble` 去加文本。

- `order` 走 `getSectionOrder(name)`；那个方法对**没见过的名字可能抛**，所以整段包在 `try/catch` 里，拿不到就退到 `60`。
- `text` 传**函数**而不是字符串 —— 这样改配置能立刻生效，不用重挂 section。
- section 挂不上时（拿不到 `systemPrompt` 服务）有**兜底**：每会话注入一次规则消息。⚠ 只注入一次 —— 每轮都塞等于每轮都付这份 token。

### 服务获取

顶层 `export const inject = []` **故意留空**。cordis 的 `Context` 是受控代理，没写进 `inject` 的服务用 `ctx.X` 访问会直接抛；用 `ctx.get(name)` + `try/catch` 更安全，**非 Web 组合（CLI / 无头）也才能激活**。

## 2. 三档预设为什么是「三张完整取值表」

`lib/core/config.js` 里 `PRESET_VALUES` 是三张**完整**的表，不是「基线 + 补丁」。

原因：如果预设是补丁，就会出现「`preset` 写着 `balanced`、但 `microCompactKeep` 还留着上次 `strict` 的 4」这种**幽灵状态**。用户看着界面显示「均衡」，实际取值却偏离了 —— 而且这种状态**不会报错**，只是行为莫名其妙。

配套的不变量有两条：

1. `normalizeConfig` 的优先级：`input.preset` 的取值表 → `input` 里显式写的单项 → `base` 兜底。
2. **「改单项就把档位标成 `custom`」由宿主侧强制**（`lib/host/http.js` 的 `/config` 分支），不是靠前端自觉。

第 2 条踩过一次：最早只在前端 `save()` 里加 `preset: 'custom'`，于是任何别的调用方（curl、模型自己、另一个插件）打 `/config` 都会造出幽灵状态。单测抓到了它。

`custom` **没有取值表** —— 它的含义就是「以传进来的值为准」。

## 3. 数据层

### 锁（`LockStore`）

语义刻意做得极简，因为用途只有一个：**让两个子代理不会同时写同一片目录**。

- `name` 人可读（`build-dir` / `port-8080`）
- `path` 这片资源对应的路径前缀（可空 = 纯命名锁，只能按名字抢）
- `owner` 持有者标识（用会话 id，能直接回答「现在是谁占着」）
- `ttlMs` **必须有过期**，否则进程崩了就是死锁

`conflictFor(targetPath, owner)` 的判据：锁的 `path` 盖住目标路径，或锁名与目标同名。**拿不准就返回 `null`（fail-open）** —— 宁可漏拦，不可误拦。

与社区 `dsh-task-queue` 的 busy-lock 同思路，但更小：不做排队、不做 aging。

### 读数台账（`EvidenceLedger`）

借自社区 `dsh-turnscope` 的「漂移即拒」，实现自己写。

记读数时把当时产物的 `sha256` 一起写下；复核时先比指纹，**对不上就直接判这条读数作废**，而不是事后人工排查「这是哪一版的数」。

一条边界：**没绑定产物的读数按「有效」处理** —— 无法核对 ≠ 作废。否则每一条手工记的读数都会被判死。

### 计数器（`Counters`）

会话级、内存态、不落盘。重启后归零是**可以接受**的：它只影响一次提醒，不是审计数据。单会话键数上限 400，防止超长会话把内存吃光。

## 4. 为什么不用 `defineTool`

与整个 Laurel 系列一致：`defineTool` 的产物就是一份编译好的 JSON Schema，`lib/host/tools.js` 直接把那份 schema 交给 `ctx.tools.register()`。

换来的好处是宿主半边**一个非内置 import 都没有** —— `@deepseek-ai/*` 能不能被解析取决于宿主的运行时解析机制，那是实现细节不是契约，少依赖一个就少一种「装上但什么都不发生」。

⚠ `required` 是**父级的字符串数组**，不是属性里的布尔值。写成布尔值会被当成未知关键字丢掉，**必填校验静默失效**且不报错。`assertRequiredShape()` 就是为这个坑设的闸门（照抄 strata 的做法，同一个坑不想踩第二次）。

> **0.2.0 订正**：这一节的前提是错的。实读宿主 `dsh-agent-loop` 的 `preStep()`，
> `agent/pre-step` 的 `decision.messages` 是 **inbox 待追加的新批次**（`this.inbox.claim(...)`
> 的结果）加一条 runtime context，完整历史要到 `buildRequest()` 才从 session surface 构建。
> **那一层通常没有旧工具结果**，所以按 `role === 'tool'` 去筛是在裁空气；旧单测能过，
> 是因为它人为往这批里塞了 20 条历史 tool 消息 —— 测的是生产不存在的输入。
>
> 现在：三档默认关闭且这一层不再裁历史；能力台账里 `historyPruning` 标 unsupported；
> 历史压缩唯一 owner 是官方 `dsh-compaction-basic`。warden 改成对**新产生的**大文本结果
> 做归档 + 有界呈现（`host/archive.js`，挂 `tools/post-execute`），原文可按路径与行区间回读。

那是宿主里工具结果的唯一形态：

```
{ role: 'tool', toolCallId, content, isError }
```

（出处：`dsh-llm` 的 `convertToolResult`）

只换 `content`、其余字段原样保留，所以消息的形状、`id`、`callId` 全都不变 —— **回放与压缩仍然能重建**。

`minChars = 1200` 的下限是刻意的：单条太短时省下的还不够占位符本身，那就别动。

## 6. 客户端半边

### 不能 `require` 任意包

官方模块系统的解析顺序写死了：platform seed 表（React / Cordis / 静态 UI 库）→ 已物化的模块 → boot graph 的行 → 已注册的 factory。其余一律抛 `require("x") missed the module table`。

所以客户端代码**没法靠 npm 依赖共享**，kit 只能在**打包时内联**。`lib/client-kit.js` 就是那份 kit，由 `scripts/build-client.mjs` 拼进 `lib/client.js`。

### ⚠ 打包器不处理「模板串里嵌套模板串」

`stripSource` 的剥注释状态机只认「反引号开始、反引号结束」，它**不理解 `${...}` 的嵌套**。所以：

```js
// ✗ 会让状态机错判字符串边界，产出坏代码（而且不报错，只在浏览器里炸）
`${a ? `x${b}` : ''}`

// ✓ 拼接用 +
`${a ? 'x' + b : ''}`
```

这条踩过一次，`new Script(bundle)` 报的是 `missing ) after argument list`，位置指向几百行之外。

### 设置页的组织方式

四个页签：**档位 / 子代理 / 上下文 / 诊断**。

- 打头的是四个大按钮（三档 + 自定义），因为打开这一页的人多半是刚被坑过，他要的是「现在给我按下去」，不是一份配置手册。
- 按钮下面是九行人话摘要 —— 比让人去读二十个数字有用。
- 逐项设置全部放在后面。
- 「诊断」页签放**事件流**：护栏坏掉时它什么都不做，所以这是唯一的可观测面。

所有控件用 `Col([...])` 包一层再交给 `Section` —— 不是因为好看，是因为**括号数得过来**。第一版手写嵌套时在四个 tab 里各少写了一个 `)`，报错位置全在几百行之外。

## 7. 失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 护栏在工具调用路径上抛异常 → 宿主里所有工具都受影响 | 每条链的每次回调整体 `try/catch`；`installXxx` 各自独立挂载，一个挂失败不影响其余 |
| 配置写坏 → 插件带 `NaN` 或半个档位跑 | `normalizeConfig` 夹值、去重、限长、未知枚举退回兜底 |
| 锁文件写坏 → 插件起不来 | 读不到 = 空表；写不进 = 只影响跨进程可见性，进程内仍按内存判定 |
| 事件日志无限长大 | 超过 512KB 砍掉前一半（与 strata 同款） |
| 长会话把内存吃光 | 单会话计数键数上限 400 |
| 配置改了要重启才生效 | 总开关 `reconcileHooks()` 热生效 —— 装上/卸下钩子，不等重启 |
| 单测假通过 | 断言条数**从注册表推导**，不写死（写死过一次，加第 5 个模块时立刻假失败） |

## 8. 测试覆盖什么

> **0.2.0 订正**：0.1.0 声称「83 项全过」，隔离副本实测是 **82/83** ——
> 过期锁用例先用 `list(Date.now()+10)` 看未来过期、再用内部真实 `Date.now()` 判断现在，
> 1ms TTL 在快机器上尚未过期。现已统一改用可注入时钟（`core/clock.js`），不再有真实时间竞速。
>
> 当前两份：`tests/smoke.mjs`（单元与数据层，90 项）+
> `tests/host-contract.mjs`（**真实宿主契约验收，54 项** —— 加载本机 app.asar 里的官方
> cordis / ToolRuntime / SystemPrompt 跑真实链路）。评审明确要求：纯 fake ctx 不再作为
> 通过宿主接线的证明，所以 R1/R2/R3/R7 的验收都在 host-contract 里做。

- **配置层**：三档预设的键完整性（防「某档少一个键 → 那一项永远失效」）、单调性、夹值、`custom` 语义、`pathIgnore` 规整、包名与版本自洽
- **数据层**：锁的冲突/刷新/过期/强制释放/坏文件 fail-open；台账的指纹一致与漂移；计数器隔离与上限；事件日志轮转
- **守卫纯函数**：`capWaitTimeout` 的四种形态、`isMutatingTool` 的 fail-open、`isIgnored`
- **钩子契约**（最重要的一节）：
  - 不拦时必须把 `next()` 的结果**原样**交还（`===` 断言，不是深比较）
  - `llm/stream` 必须交还 `next()` 的结果
  - `pre-step` 非 `enter` 不碰；改写后 `startsRequestSeries` 还在
  - `additionalContexts` 里出现 warden 提醒，且下游的其余字段没丢
  - **内容不同的两次 edit 也算返工**（宿主自带的算不出来）
  - 忽略名单里的路径产生零提醒
  - 总开关关掉时三条链都不动任何东西
  - `dispose()` 之后钩子全部卸载，不留半个监听器
- **HTTP 数据面**：五个端点 + 404 / 405 + 「改单项自动标 custom」这个不变量
- **工具**：schema 形状（`required` 必须是父级数组）、加锁/列锁/释放端到端、台账记录与复核端到端

跑法：`npm test`。**零依赖**，克隆下来就能跑。
