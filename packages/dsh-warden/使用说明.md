# 内耗护栏 · 使用说明

打开 **设置 → Laurel 套件 → 内耗护栏**（单独装的话是「设置 → 内耗护栏」）。

一句话版本：**先选一档，跑一段时间，再看「诊断」页签决定要不要逐项微调。**

---

## 一、先选一档

四个大按钮：

- **温和** —— 只提醒，几乎不拦。适合你本来就打算自己盯着的时候。
- **均衡** —— 默认档。该拦的拦、该提醒的提醒。
- **严格** —— 等待压到 30 秒、重复 2 次就提醒。适合无人值守的长时间任务。
- **自定义** —— 以你下面逐项设的值准。你改任何一项，会自动切到这里。

按钮下面是**「这一档具体是什么」**：九行，把当前生效值用人话列出来。不用去读二十个开关。

底下是**总开关**。关掉 = 三条钩子全部卸载，等于这个插件不存在。**不用重启**。

> 注意：这一档只约束「怎么协作」，不改变模型本身的能力。它拦不下沙箱权限、网络这些系统层的事 —— 那些见 [系统层问题与提示词.md](系统层问题与提示词.md)。

## 二、三个页签里各是什么

### 子代理

**等待上限（毫秒，0 = 不干预）**

`wait_agent` 是「等某个子代理干完」。宿主的硬超时对它无效，等多久是模型每次自己填的，上限一小时。实测一个会话里它被调 41 次，486 步的会话跨度 6 小时、真正在算的只有 73 分钟。

- 想完全不干预 → 填 `0`。
- 一般填 `60000`（60 秒）。子代理真的还在干活的话，60 秒后再等一次就是了；**干等一小时**才是问题。

**子代理只对主控汇报（星型拓扑）**

打开后，会往系统提示词里加一段常驻规则：子代理只向主控汇报，不要给其他子代理发消息、不要互相「更正」。

实测一个会话 98 条 team message 全是子代理互相纠错，读数互相污染 —— 最后谁都说不清哪个数是谁测的。这条是**规则**不是**拦截**（拦不住它们发消息，但写进提示词后模型会遵守）。

**子代理结论写文件**

子代理只把「文件路径 + 一行摘要」回给主控，不把大段结论贴进对话。Anthropic 官方管这个叫「减少传话游戏式的信息失真」——转述三次之后，结论基本就变形了，而且主控上下文会迅速膨胀。

**共享目录锁 / 锁自动过期**

只拦「写」，不拦「读」。下面列出当前持有的锁，可以**强制释放**（确认对方进程已经死了再用）。

⚠ 锁必须有过期时间，否则进程一崩就是死锁。默认 2 分钟。

**能物理隔离就隔离**（各自一个目录 / git worktree），比排队等锁省时间得多 —— 这是 Git worktree 和 Claude Code 的共识。锁只是给「端口、数据库、全局开关」这类真正没法隔离的资源兜底的。

### 上下文

**增长式水位提醒 + 每长大多少 token 提醒一次**

宿主的自动压缩只在窗口到 80% 时才动手（1M 窗口 = 80 万 token），长会话常常到不了。这里改成「每长大一定量就温和提醒一次」，与窗口大小无关。**只提醒，不删改任何历史。**

水位数取自**宿主上报的用量**。拿不到就不提醒 —— 这个插件自己的估算只用于显示，不拿来记账。

**大输出归档（「微压缩」已废弃）**

超过阈值的**新**工具结果会先完整写到本地文件，上下文里只留有界摘要 + 行数 + 字节数 + sha256 + 文件路径。要中间部分就按行区间读那个文件 —— **不要重新执行刚才那个工具**，写入/部署/网络请求重跑一次就有副作用。

旧的「微压缩」开关还在，只是为了兼容旧配置文件：三档全部默认关闭，打开也不会有任何裁剪行为。原因是 `agent/pre-step` 拿到的是待追加的新消息批次，里面没有历史工具结果可裁；历史压缩的唯一 owner 是官方 `dsh-compaction-basic`。

只动 `role=tool` 的消息，只换 `content`，`id` / `callId` / 其余字段原样保留 —— 所以回放与压缩仍然能重建。

宿主的 `tool-result-pruner` 只治「单条超长」（阈值 8192 字符），治不了「很多条中等长度堆在一起」。这里按**条数**再削一层。

**返工提醒 + 同一文件改到第几次提醒**

按「**同一个文件**」计数。

宿主自带的 `dsh-repeat-tool-reminder` 是按「同一次调用」算的 —— 两次内容不同的 edit **不算重复**。而实测最烧时间的返工恰恰是「同一个文件改了 31 次」，每次内容都不一样。这一条正好补上那个洞。

**重复读提醒 + 同一文件读到第几次提醒**

实测一个文件被读了 60 次。读没变的东西等于白烧 token。

### 诊断

**失败时的提示**

- 改文件没匹配上 → 提示「先完整重读再改」。实测 8 次 `old_string was not found`。纯文本匹配本来就脆（文件被上一轮改过、全角括号、换行差异都会失配）。
- 未知工具 → 附上**当前 agent 的真实工具清单**。实测 4 次 `unknown tool`。

⚠ 这两条**只在调用已经失败时**才触发，所以不可能误伤正常调用。

**读数指纹台账**

记读数时把当时产物的 `sha256` 一起写下；复核时先比指纹，对不上就**直接判这条读数作废**。

治的是「验收期间部署换了三次，读数无法归属」——谁都能拿一个数说「我测的是最新版」，而指纹对不上就是一句话的事。

**忽略名单**

本插件对这些路径**完全不介入**（不查锁、不发提醒、不记账）。适合 `node_modules/`、`.git/`、构建产物目录这类「本来就会反复读写、提醒只会变成噪声」的地方。

⚠ 这**不是**「给沙箱放行」的开关。插件层没有权限绕过文件系统级的 `cannot read` / `cannot modify` —— 那是系统层的事。

**运行时统计与事件**

三条钩子链各自拦了多少、提醒了多少，以及**最近事件流**（它到底做了什么）。护栏坏掉时它什么都不做，所以这是唯一的可观测面。

## 三、可以直接对模型说的话

护栏的自动部分不用你说什么。下面这些是**让模型用上那 6 个工具**的话。

### 共享资源锁

> 你要写 `D:\build\out` 之前，先 `acquire_lock` 拿一把锁（name 用 `build-dir`，path 写 `D:\build`），干完 `release_lock` 放掉。

> 你现在要改的这个目录，可能有别的子代理在用。先 `list_locks` 看一眼。

### 读数归属

> 每次测出一个数，都用 `evidence_record` 记下来，`artifact` 填你测的那个 exe 的路径。以后引用这个数之前，先 `evidence_check` 确认产物没变。

> 这条读数是哪一版测的？`evidence_check` 一下。对不上就别用。

### 状态自查

> 先跑 `warden_status`，告诉我现在护栏是什么档位、有哪些开关开着。

### 派活给子代理时（配合星型拓扑）

> 你负责 `<目标>`。做完把结论写到 `probe/<你的角色名>.md`，**只回我文件路径 + 一行摘要**，不要贴大段内容。不要直接联系其他子代理，需要协作就告诉我。

> 边界：**不要**碰 `<哪些不做>`。不确定就停下来问我，不要自己扩大范围。

（第三条里的「边界」是必须写的 —— 实测不写边界时子代理会重复劳动或留空。）

### 上下文快满了的时候

护栏会自己提醒。收到提醒后可以说：

> 把已经确定下来的结论写进 `<文件>` 或长期记忆，然后我们收尾这件事，开一个新会话继续。

## 四、出问题怎么查

| 现象 | 先看哪里 |
|---|---|
| 在「Laurel总控」里点它的开关，提示 `操作未成功：内耗护栏:operation-error` | 包**还没装进 profile**（源码里有它、profile 的 `node_modules` 里没有）。先**完全退出** Harness（含托盘），在套件目录跑一次 `node scripts/install-profile.mjs`，再启动。想提前发现：`install-profile.mjs --check` 会直接报「`dsh-warden` 断链」 |
| 开了但什么都没发生 | 「诊断」页签的**运行时统计**。三条链都显示 `{}` → 钩子没挂上，看 Harness 控制台有没有 `[warden]` 开头的告警 |
| 提醒太吵 | 换「温和」档；或把 `node_modules/`、构建目录加进**忽略名单** |
| 提醒太少 | 换「严格」档；或把「同一文件改到第几次提醒」调小 |
| 子代理被拦得干不了活 | 「子代理」页签看是不是有死锁没释放 → **强制释放** |
| 想确认它到底改了什么 | 「诊断」页签的**事件流**；数据在 `$DSH_HOME/warden/`（`settings.json` / `locks.json` / `evidence.jsonl` / `events.log`） |

**所有数据都在你自己电脑上**，插件不联网。

## 五、它做不到什么（别指望）

- **拦不住沙箱权限。** `cannot read` / `cannot modify` 是系统层的，插件绕不过去也不该绕。
- **不能改工具的参数。** 它只能在工具执行前放行/拦下、执行后补一句提醒 —— 这和 OpenAI Agents SDK 的 guardrail 边界一致（guardrail 不该悄悄改参数，否则你没法从日志里复原发生了什么）。
- **不保证子代理真的听话。** 星型拓扑是**提示词规则**，不是强制隔离。真要做到互不可见，得靠物理隔离（不同工作目录 / git worktree）。
- **不替你判断读数对不对。** 台账只保证「这条读数是哪个产物测的」，不保证测的方法是对的。
